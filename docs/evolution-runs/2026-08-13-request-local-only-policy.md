# 2026-08-13 · 请求级离线与长期记忆边界

## 假设与参照

- 主假设：用户明确说“不要联网 / 不写入长期记忆”时，如果约束只影响 Agent 路由，主模型、独立 Embedding、工具或失败记录仍可能绕过用户意图；把约束提升为请求级策略，并在每个副作用入口执行，能补齐这个缺口。
- OpenCode 参照点：`vendor/opencode/tools/fetch.go` 在 `client.Do` 前申请 fetch 权限，`write.go` / `edit.go` 在文件修改前申请写权限。本轮借鉴“副作用前裁决、执行层再次拒绝”的顺序，不复制其代码或通用权限系统。
- 评测数据：`XCG-core-agent-gates` v1 的 E08 合成占位文本；不含真实凭据、聊天正文、论文正文或用户绝对路径。
- 迭代类型：产品安全边界与核心门禁补证；没有更换或调用 Codex/小妍模型，不登记为模型升级。

## 失败面审计

上一轮已经让“不要检索或联网，只根据当前材料”跳过 retrieval、literature_scout、survey 和不必要的 supervisor，但完整请求仍有四个独立出口：

1. `run_chat` 在路由前构造并调用主模型；
2. 查询与来源召回可能调用独立 Embedding 端点；
3. 直答工具循环仍可能执行 Web、arXiv 或嵌套模型工具；
4. 全局长期记忆开启时，prompt、完成、失败与 checkpoint 仍会持久化单次敏感请求。

因此，Agent 路由收窄是必要但不充分的边界。

## 实现契约

新增 `ChatRequestPolicy` 作为 service 层唯一请求策略入口：

- “不要联网 / 只在本地或本机处理 / offline only”进入 `local_only`；
- 实际将被调用的文本或视觉模型仅允许 `localhost`、`*.localhost` 与 IP loopback；远程、局域网和伪 localhost 域名均在模型调用前拒绝；
- 离线请求不调用独立 Embedding，也不启动后台 observation embedding 回填；本地词法检索仍可使用；
- Web、arXiv、综述生成和规划生成从工具定义中移除，dispatcher 再做一次拒绝；
- “不要写入长期记忆”覆盖全局开关，关闭 prompt、完成、失败 memory event 与 checkpoint；同一份请求 settings 传入嵌套操作；
- 未明确要求创建资产时，笔记与实验写入工具也从模型能力集中移除；“保存为笔记 / 创建实验”等明确请求仍作为用户主动创建产品资产的单独授权。

普通请求不改变网络、Embedding、工具或全局记忆行为。

## 决策与剩余风险

- 决策：采纳请求级策略和执行层纵深防御。
- 不宣称：E08 的模型输出已脱敏；E01/E02 的端到端任务质量已提升；完整核心门禁已通过。
