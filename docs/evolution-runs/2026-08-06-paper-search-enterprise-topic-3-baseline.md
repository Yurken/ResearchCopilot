## 本轮假设卡

- 用户问题：现有论文查找只能完成一次性查询与列表推荐，难以覆盖复杂学术查询的自主迭代和可评测成本要求。
- 主假设：如果把查询意图、检索步骤、引文扩展、相关性分层和单次成本统一为类型化检索管线，那么复杂查询的覆盖与可解释性会提升，同时能显式约束 API 和 Token 成本。
- 目标用户与场景：需要从细粒度自然语言问题找到全面、精准论文集合的研究者；对应华为企业赛题三。
- 当前基线：支持 2—4 条查询拆分、Semantic Scholar 多查询合并、启发式/LLM 重排与列表展示。
- 目标变化：PS01—PS05 的所有结构断言可由返回契约和自动测试验证；网络质量 F1 留待接入公开/隐藏数据集后测量。
- 最便宜验证：先用合成固定夹具验证管线行为，再用 PaSa/AstaBench 子集做联网 F1 与成本测量。
- 杀停标准：相关性排序回归，快速模式 API 调用不可控，或引文扩展失败会丢失首轮结果。
- 对应评测：PS01—PS05；核心护栏 E02、E06、E08。
- 端到端切片：工具页输入复杂问题 → 选择成本档位 → 查看意图、步骤、指标、相关性分层与论文关系。
- 代码边界：Rust 检索策略独立模块；前端远程编排从超长 hook 抽离；结果解释与关系视图独立组件。
- 隐私影响：只处理用户主动提交的查询；历史仍留在本地 SQLite；不新增远程遥测。
- 回滚方式：保留快速模式与首轮 Semantic Scholar 结果作为降级路径。
