# 企业赛题三标准：智能论文搜索与推荐完善计划

主参照标准：第八届中国研究生人工智能创新大赛华为企业赛题三「科研场景下复杂学术查询的智能论文搜索与推荐」。

使用定位：本计划借用赛题题面完善小妍产品能力，不要求实际报名、提交作品或达到官方测试分数。功能完成以“条款已转成产品行为 + 固定代表场景可走通”为基本门槛；LitSearch、PaSa、AstaBench 和 F1 属于有条件时使用的增强证据，不替代真实产品场景，也不阻塞没有官方数据集时的合理改进。

官方依据：[企业命题赛题发布页](https://cpipc.acge.org.cn/cw/contestNews/detail/2c9088a5696cbf370169a3f8101510bd/2c9080179e403028019e496a8feb14b9?page=0)及其华为赛题附件（`fileId=4bff16a402754033bb8ec9fca03cee0b`）。

## 官方赛题要求（附件原文要点）

### 题目描述（挑战）

- 复杂细粒度研究问题 → 全面且精准的相关论文集合；需语义意图、多轮检索、引文网络、跨文献关联。
- 现有挑战：查询理解不充分（主题/方法/数据集/时间/venue 等多维约束）；召回与噪声平衡；权威性/时效性/相关性/多样性权衡；按意图归纳并**结构化展示**。
- 期望：端到端系统，完成查询理解 → 多维度多策略检索 → 综合排序 → 结果归纳整理。

### 3.1 核心功能要求

1. **查询理解与分解**
   - 解析自然语言中的核心研究意图，识别关键实体、方法论约束、数据/领域限定等多维条件
   - 复杂查询子查询分解，拆为可独立检索的子问题
   - 查询改写与扩展，生成更适合检索引擎的查询
2. **基于大模型的自主搜索策略迭代优化**
   - 自主规划搜索词进行搜索
   - 过滤不相干、低质量论文
   - 迭代式检索：根据已找到的相关论文信息，动态调整策略与关键词
3. **论文综合排序**
   - 基于标题、摘要及可用全文做细粒度相关性评估
   - 输出排序列表，**区分高度相关与部分相关**
4. **搜索结果归纳整理**
   - 按查询意图自主整理，结构化展示（**列表、关系图等**）

### 3.2 技术要求

- 可使用开源或商业 LLM（需注明模型及版本），鼓励开源（如 Qwen、DeepSeek）
- 检索后端需对接**至少一种**学术搜索 API（Semantic Scholar、OpenAlex、PubMed 等）
- **成本控制**：评分考虑 API 调用次数、Token 消耗量

### 4. 评测标准

| 指标 | 权重 | 说明 |
| --- | --- | --- |
| F1 Score | 70% | 精确率与召回率平衡 |
| 运行效率 | 20% | API 次数、Token、端到端延时 |
| 回复结果结构化 | 10% | 列表、关系图等 |

成绩：竞赛得分 60%（公开测试集 30% + 隐藏测试集 30%）+ 专家评分 40%（创新性 15%、落地可行性 15%、泛化性 10%）。

参考数据集： [PaSa](https://github.com/bytedance/pasa)、[AstaBench](https://github.com/allenai/asta-bench)；文献亦引用 LitSearch 等。

## 固定产品验收场景

这些场景用于 L2 产品走查，不要求官方 gold 或专职测试人员。每次触达检索主流程时至少走查受影响场景，并记录失败与已知限制。

| 场景 | 输入与操作 | 可观察验收 |
| --- | --- | --- |
| UX01 复杂约束检索 | 输入同时包含主题、方法、数据集/领域和时间限制的自然语言问题 | 意图字段与限制可检查；产生互补且不重复的查询；结果分层并带来源 |
| UX02 描述型问题 | 不提供准确论文名或术语，只描述想找的方法/现象，分别使用快速与均衡模式 | 能解释查询改写；均衡模式可使用正文片段或引文补充；不把片段伪装成摘要 |
| UX03 失败与降级 | 模型未配置、部分 API 限流或某轮返回空数据 | 保留可用的确定性结果；失败步骤、降级原因和成本账单可见；页面不白屏 |
| UX04 用户修正 | 用户调整时间、排除词或搜索深度后重新搜索 | 新限制进入请求和轨迹；历史结果可区分；成本变化可比较 |
| UX05 结果使用 | 从推荐结果打开来源并选择值得保存/继续阅读的论文 | 标题、作者、年份、来源链接和相关性理由足以支持用户判断；不可核验字段不伪装为确定事实 |

## 分阶段建设

1. **可走查检索管线**：冻结 PS01—PS05 和 UX01—UX05，扩展请求/响应契约，完成预算、步骤、指标与失败降级。
2. **引文网络探索**：基于首轮高价值种子扩展引用与参考文献，去重后进入统一排序。
3. **可解释结果工作区**：展示意图、查询、轨迹、相关性分层、关系边和成本。
4. **可选量化证据**：已接入 LitSearch 597 条查询和可重复运行器；只有在数据合法可得且确实服务产品判断时，才继续接入经用户授权的 PaSa / AstaBench 子集，报告 Precision、Recall、F1、API 次数、Token 与 P50/P95 延时。
5. **可复现产品工程化**：固化运行配置、缓存、离线回放与设计说明。公开/隐藏测试集提交接口仅在实际参赛时另行立项，不属于默认产品路线。

前 3 项与 UX01—UX05 是产品完成基础；第 4 项是增强证据，必须使用合法获取的数据和可复现实验，不在没有运行结果时宣称 F1 提升，也不因暂时没有新数据集阻塞场景明确的产品修复。

## 当前评测证据（2026-08-09）

- LitSearch 原始 Parquet 已固定官方 revision、SHA-256 并转换为本地 JSONL；数据目录不进入 Git。
- 全量离线查询规划评测覆盖 597 条：无空计划、无重复检索式，596 条长问题全部压缩，首查询平均 5.08 词，P95/最大值为 8。
- 574 个唯一 gold Corpus ID 已通过 Semantic Scholar batch API 固化规范 `paperId` 与 Corpus ID 别名，572 个成功解析；快照可用于离线诊断，避免知识图谱 ID 迁移造成误判。
- 固定前 80 条 Quick 切片共有 100 个官方 gold：扩容初始命中 57/100，摘要字段修复后仍命中 83/100；Recall@5 0.74、Recall@10 0.77、Recall@20 0.83、Precision@20 0.0527、F1@20 0.0991。160 次逻辑 API 调用全部命中本地缓存，严格离线墙钟时间 930 ms；前 40 条仍保持 42/53，无退化。
- 其中 2 个旧 gold Corpus ID 当前无法由 Semantic Scholar batch API 解析；报告保留官方分母，同时提供当前可解析口径 83/98、Recall@20 0.8469，不用过滤不可达目标制造更高官方分数。
- `litsearch-0003` 的两篇方言阿拉伯语分词 gold 从 Top-20 外提升至第 3、4 名；后 40 条新增找回 FEVER、fastText、MiniLMv2、QDMR、Sentence-BERT、CrossWeigh 等描述型请求。SRL 旧共享任务在 Quick 模式命中 1/3，Deep 引文扩展命中 2/3，仍是下一轮重点。
- 关系接口现可容忍 `data: null` 与单条论文空字段，成功响应在解析通过后才缓存；429 重试尊重 `Retry-After`。深搜单个种子的关系页由 20 扩至 100，逻辑调用次数不增加。
- PaSa 与 AstaBench 下载需要用户在 Hugging Face 接受 gated 数据条款；在授权前保持 `requires_user_license_acceptance`，不使用镜像规避。
- 固定种子分层 80 清单的 80 个 case 已严格离线回放，覆盖 4 个 query set 和 16 个 `query_set × specificity × quality` 组合：28/91，Recall@20 0.3077。160 条逻辑查询中 157 条命中缓存，3 条次查询缺失并由同 case 的另一条成功查询降级；需在联网额度恢复后补齐。`inline_acl` 为 0.6190，`inline_nonacl` 0.2222，`manual_acl` 0.25，`manual_iclr` 0.1429；差距主要来自查询来源，而不是 specificity 或 quality。
- Balanced/Deep 已接入 Semantic Scholar 正文片段召回，再用 batch API 补齐正式元数据；片段作为内部召回/排序信号，与摘要严格分离。固定分层清单第 61—72 条中，Quick 命中 1/12，Balanced 命中 8/12（Recall@10/20 0.6667），8 个 gold 均由全文片段路径贡献。Quick 继续保持每条 2 次论文级调用；Balanced 不扩展引文，Deep 才保留引文网络。
- Semantic Scholar 三类响应的 `abstract` 字段现已显式映射；修复后分层 Quick 从 27/91 提至 28/91，连续 Quick-80 Top-20 持平、Top-5 从 72 提至 74，未通过错误字段名静默丢弃摘要。
- 已建立下一轮未触碰 holdout：seed `20260810`，排除 Quick 前 80 条和当前分层清单的并集 148 条，新选 80 条与旧切片零重叠且字节级可复现。排除后一个 5 条小分层已耗尽，清单显式记录空层并覆盖其余 15 个组合；尚未检查 gold 或运行检索。
- holdout 离线规划门禁已覆盖 80 条：无空计划、无重复检索式，79/79 条长查询全部压缩，首查询平均 5.21 词，P95/最大值均为 8；该步骤不访问 gold，不消耗检索门禁。
- 新增同 case 成对比较器，强制核对 case、query、gold、截止日期与 Top-K 口径。引文消融确认 Balanced 的 12 条 Top-20 全部不退化、调用从 78 降至 54，Top-5 增加 1 个命中。成本优化后相对 Quick 改善 7 条、退化 0 条，净增 7 个 gold；只增加 30 次学术 API 调用，折合每 case 2.5 次、每净新增 gold 4.29 次。

- 智能规划评测必须显式 `--with-local-llm`，避免默认产生模型费用；报告记录模型名、调用数与估算 Token。当前本地兼容端点返回 401，单例没有形成有效改进证据；代码已支持论文专用模型失效时运行时回退小妍主模型，但本机暂无第二个可用端点。

## LitSearch 适用性审计与停止决定（2026-08-11）

LitSearch 适合验证“复杂自然语言问题能否找回一个或多个已知目标论文”，与企业赛题三的查询理解和论文召回方向一致；但官方评测使用配套封闭论文语料，而当前小妍评测只复用了 query/gold，并在实时 Semantic Scholar 开放全库中搜索。开放世界存在大量未标注但仍相关的论文，因此当前 Precision/F1 不能与 LitSearch 官方结果横向比较，也不能单独代表赛题效果。

- 候选级诊断显示：Quick 前 80 条的 100 个 gold 中，83 个进入候选且全部进入 Top-20，17 个是召回缺失、排序损失为 0；分层 80 条的 91 个 gold 中，31 个进入候选、28 个进入 Top-20，3 个是排序损失、60 个是召回缺失。
- 摘要覆盖与连字符词形加权曾让分层集 Top-20 增加 1 个 gold，但使 Quick 前 80 条从 83/100 退化到 78/100、5 个 case 退化，门禁已拒绝并撤回代码；恢复后 Quick 回到 83/100。
- 决定停止以当前 LitSearch 开放世界改编结果驱动继续调参，取消尚未运行的 holdout 联网计划。现有数据只保留为已知目标召回、成本和故障回归集。
- 后续若重新开启质量优化，必须使用官方封闭 corpus 复现原始口径，或建立覆盖中文/英文、多学科、结果相关性人工标注和用户任务完成度的赛题对齐评测；不能把单一 gold 未命中等同于产品结果不相关。

本地 `iteration-105/106` 记录候选归因，`iteration-111` 记录被拒绝的排序实验，`iteration-112` 记录恢复结果；这些可再生成 JSON 不进入 Git。
